## Audit findings

Counts before cleanup:

- **`permissions.allow`**: 344 entries (343 + 1 from concurrent edits)
- **`permissions.deny`**: 4 entries
- **`permissions.additionalDirectories`**: 11 entries

### Findings

1. **JWT tokens in `allow` entries** — 9 entries contained full JWT bearer tokens in plaintext (`Bash(TOKEN="eyJ..."`). Even though all tokens are expired (1h TTL × creation timestamps from prior sessions), each JWT base64-decodes to reveal: user email, userId GUID, role, mobile phone, audience URI, issuer URI. PII exposure in source-controlled file. **Removed all 9.**

2. **One-off UUID-laden entries** — 9 entries contained specific event IDs or registration IDs from past staging smoke runs. Examples: `Bash(EVENT_ID="d543629f-08e3-4e5a-82f7-dede86c62a12" curl ...)`. These never match any future invocation and just pollute the allow list. **Removed all 9.** Future curls against staging are already covered by broader `Bash(curl -s -X 'POST' 'https://lankaconnect-api-staging...':*)` wildcards.

3. **Production write commands** auto-allowed — 4+ entries gave Claude write access to `lankaconnect-prod` resources without prompt. Examples: `az containerapp revision deactivate --resource-group lankaconnect-prod`, `MSYS_NO_PATHCONV=1 az containerapp show --name lankaconnect-ui-prod`. Per CLAUDE.md "executing actions with care," prod writes should require explicit prompt. **Mitigated via deny-list expansion (see below).**

4. **One-off cleanup artifacts** — `Bash(rm -f scripts/create_b4_tiered_test_event.py.bak)` and similar tracked specific test-file paths. Cleanup is a one-time operation; no value in caching the entry. **Removed.**

5. **`additionalDirectories` duplicates** — 11 entries with 4 different surface forms of `/tmp`: `\tmp`, `/tmp`, `c:\tmp`, `C:\tmp`. Azure/Windows is case-insensitive for filesystem paths. **Collapsed to 10 entries** (case- and slash-normalized).

6. **No `ask` entries** — every action is binary allow/deny. Medium-risk operations like `gh pr merge` or `git push --force-with-lease` should ideally prompt. Not addressed in this audit (would require schema knowledge of `ask` block + behavioral testing); flagged as follow-up.

### New `deny` rules (15)

**Production resource group blocks (4)**:
- `Bash(az * --resource-group lankaconnect-prod *)`
- `Bash(az containerapp * --name lankaconnect-api-prod *)`
- `Bash(az containerapp * --name lankaconnect-ui-prod *)`
- `Bash(az postgres * --server-name lankaconnect-prod-db *)`

**Destructive git (5)**:
- `Bash(git push --force *)`
- `Bash(git push -f *)`
- `Bash(git reset --hard *)`
- `Bash(git clean -f *)`
- `Bash(git branch -D *)`

**Destructive SQL (2)**:
- `Bash(psql * -c *DROP *)`
- `Bash(psql * -c *TRUNCATE *)`

**Destructive EF migrations (2)**:
- `Bash(dotnet ef migrations remove *)`
- `Bash(dotnet ef database drop *)`

**Filesystem destruction (2)**:
- `Bash(rm -rf *)` — broader than the existing `Bash(rm -rf /)` rule
- `Bash(find * -delete *)`

## What was NOT changed (intentional)

- **The remaining 326 `allow` entries** — these are wildcarded patterns (`Bash(az containerapp *)`, `Bash(npm test *)`, etc.) that are legitimately reusable. A "collapse to fewer wildcards" pass could shrink this further, but each entry costs nothing and the cleanup ROI is small.
- **`hooks` section** — not audited in this pass. Future audit if hook misbehavior surfaces.
- **`enabledMcpjsonServers`** — `claude-flow` + `ruv-swarm` are intentionally enabled; leaving alone.
- **`env`** — Claude Flow tuning vars; intentional.
